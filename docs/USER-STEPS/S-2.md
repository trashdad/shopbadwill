# USER STEP S-2: session token facts (about 10 minutes, plus a day-2 check)

**Why you:** the extension never stores your password. It reuses the login you already have. These steps measure how long that login lasts and whether the site renews it by itself. That decides whether sniping while you sleep is possible.

**Never paste, into chat or any file:** the token (anything starting `eyJ`), the `Authorization` header, the cookie `cookieSession_8`, the refresh token, or your password. Do not use "Copy as cURL" or HAR export. You paste back only yes/no answers, field names and the script's output.

Use your normal browser, logged in to shopgoodwill.com. Do not log out. Do not log in again during the check.

## a. Is the bearer header visible? (2 min)

1. On any shopgoodwill.com page, press F12 and open the **Network** tab. Tick **Preserve log**.
2. In the filter box type `buyerapi`. Reload the page (F5).
3. Click one request in the list, then the **Headers** tab, then scroll to **Request Headers**.
4. Report **yes/no**: is there an `Authorization: Bearer ...` header? Also name the request type shown (Fetch/XHR). Do not copy the header into the chat.

## b. Token lifetime, measured locally (3 min)

1. In the same request, select only the long text **after** `Bearer ` in the `Authorization` value, and copy it (Ctrl+C).
2. In PowerShell, in `C:\tools\shopbadwill`, run (this form keeps the token off the terminal screen):
   ```powershell
   Get-Clipboard | pnpm exec tsx scripts/jwt-claims-only.ts
   ```
3. The script runs offline and prints only claim names, `iat`, `exp`, `exp - iat` and two yes/no lines. **Look at the output before pasting; it should only contain claim names and dates.** Paste back **that output only**.
4. Then clear the clipboard: `Set-Clipboard -Value ' '`.

If it prints `Refused: ...`, you copied the wrong text. Do not paste the text you copied.

## c. Does the site refresh by itself? (3 min)

1. In the Network filter type `RefreshToken`. Clear the log, then browse SGW normally for about 2 minutes (open a search, an item, the home page). Leave the tab open a few more minutes.
2. Report **yes/no**: did a `SignIn/RefreshToken` request appear on its own? If yes, roughly when (on page load, on a timer, after a 401) and its status code.
3. If yes, click it, open the **Payload** tab, and report the **field names only** (not values). Also say whether its response contained a new token (yes/no; do not paste it).

## d. The two-day check (about 1 minute per day)

1. Close the SGW tab. Do not log out and do not click any login button.
2. **Tomorrow** (at least 24 hours after you last used SGW): open shopgoodwill.com. Report: still logged in (yes/no)? If it asks you to log in, report that first; logging in again is fine after you have reported.
3. If still logged in, do not touch anything. **Day 2** (48 hours or more after last use): open it again and report the same.

Note the time of your last real visit, to the nearest hour, in each report.

## Paste back

1. a: yes/no, request type
2. b: the script output
3. c: yes/no, when, status code, field names, new token in response yes/no
4. d: day 1 and day 2 results with hours since last visit
