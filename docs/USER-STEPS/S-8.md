# USER STEP S-8: wake-from-sleep tests (about 60-90 minutes, mostly waiting)

Goal: find out whether this laptop can stay awake or wake itself for an auction ending while you sleep. Five measurements (criteria 1-5). Do them in order. Nothing here touches shopgoodwill.com or your account.

What changes on your machine, all reversible and all listed: a throwaway Chrome extension (unpacked), one temporary scheduled task per run (the script removes it itself), and, in step 2 and optionally step 3.5, a temporary power-plan change that you restore.

**Never paste:** passwords, cookies, tokens, anything from Chrome's profile folder. You will only paste timestamps and `powercfg` output.

Use the worktree's files: `C:\tools\shopbadwill-wt\T-14\` (after merge: the repo root). Below, `$R` means that folder.

## 0. Preparation

0.1. Open PowerShell (normal, not admin) and set the root:
```powershell
$R = 'C:\tools\shopbadwill-wt\T-14'
$P = "$env:LOCALAPPDATA\ShopBadwill\probe"
```
0.2. Plug in the charger. Keep it plugged in for every test (unless a step says otherwise).
0.3. In Chrome open `chrome://version` and note **Profile Path** (for example `C:\Users\insan\AppData\Local\Google\Chrome\User Data\Default`). Split it: the part before the last folder is the user-data dir; the last folder is the profile. Set (edit to match yours):
```powershell
$UD = "$env:LOCALAPPDATA\Google\Chrome\User Data"   # user-data dir
$PR = 'Default'                                      # profile folder name
```
(On this machine that folder was empty when checked, so your real profile may be elsewhere; use what `chrome://version` says.)
0.4. Dry run of the script (changes nothing, creates no task):
```powershell
powershell -ExecutionPolicy Bypass -File "$R\companion\windows\probe\wake-probe.ps1" -WhatIf -LaunchChrome -ChromeUserDataDir $UD -ChromeProfile $PR -Label dry
```
Expected: a `SCHEDULED` line and `DRYRUN_PLAN` and "Dry run: nothing registered". If it errors, paste the error and stop.
0.5. Load the probe extension: Chrome, `chrome://extensions`, turn on **Developer mode**, **Load unpacked**, pick `$R\companion\windows\probe\ext`. Pin its icon (puzzle piece menu). Click the icon; the page should show a heartbeat count that grows by 1 per minute.

## 1. Criterion 1: `background` permission, Chrome survives window close, starts at login

1.1. Baseline without the permission. Chrome `chrome://settings/system`: set **Continue running background apps when Google Chrome is closed** to OFF. Click the probe icon and press **Add MARK**, type `baseline-start`. Close ALL Chrome windows. Check Task Manager: no `chrome.exe` should remain (if some remain, end them). Wait 5 minutes. Reopen Chrome, open the probe page, **Add MARK** `baseline-end`. Expected: the heartbeat log has a gap between the two marks (browser was closed).
1.2. Grant the permission. In the probe page click **Request "background" permission** and accept. Page shows `background permission: GRANTED`. Then in `chrome://settings/system` turn **Continue running background apps...** ON. Open `chrome://extensions`, note whether the probe shows anything like "Allowed to run in background" (screenshot optional, describe it in your reply).
1.3. Survive window close: **Add MARK** `bg-start`, close ALL Chrome windows. Look at the system tray (^ arrow): a Chrome icon should remain. Wait 10 minutes. Reopen Chrome, **Add MARK** `bg-end`. Note: heartbeats continue between the marks (no gap) = pass.
1.4. Start at login: run in PowerShell and keep the output:
```powershell
reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run | findstr /i chrome
```
Then **sign out of Windows and sign back in** (Start, your name, Sign out; do not shut down). Do NOT open Chrome. Wait 3 minutes, then open Chrome, **Add MARK** `login-check`. Pass = heartbeats exist during the time before you opened Chrome and a `startup` entry appears around login time.
1.5. Export: probe page, **Export JSON**. Save as `step1-export.json` in `Downloads`.

## 2. Criterion 2: `power.requestKeepAwake('system')`

The plan currently has Sleep after = Never (AC and battery), so first make the machine WANT to sleep. This is a temporary change.

2.1. Settings, System, Power & battery, Screen, sleep & hibernate timeouts: set **When plugged in, put my device to sleep after** to **2 minutes** (screen off any value). Write down the previous values (powercfg showed: Never / Never).
2.2. Keep-awake OFF test: in the probe page make sure the toggle is OFF, press **Add MARK** `ka-off-start`. Do not touch the keyboard/mouse for 6 minutes (leave Chrome open). If the machine sleeps, press a key to wake it. Then **Add MARK** `ka-off-end`. Expected: a heartbeat gap = it slept (that is the control; it proves the test works).
2.3. Keep-awake ON test: tick **power.requestKeepAwake('system')**, **Add MARK** `ka-on-start`. In an **elevated** PowerShell (Run as administrator) run once and paste the output:
```powershell
powercfg /requests
```
(Look for an EXECUTION/SYSTEM line naming chrome.) Leave the machine untouched for 8 minutes. **Add MARK** `ka-on-end`. Pass = no heartbeat gap. (The screen may turn off; that is fine.)
2.4. Manual sleep still works with it ON: leave the toggle ON, **Add MARK** `manual-sleep-start`, then Start, Power, **Sleep**. Wait 3 minutes. Press a key. **Add MARK** `manual-sleep-end`. Expected: gap in heartbeats = Windows still slept = keep-awake does not block manual sleep. Optional: repeat by closing the lid for 3 minutes.
2.5. Restore: Settings, back to the previous timeouts (Never on AC and battery), and untick the keep-awake toggle. Verify with:
```powershell
powercfg /q SCHEME_CURRENT SUB_SLEEP STANDBYIDLE
```
(AC and DC index should be `0x00000000` again.) Export JSON as `step2-export.json`.

## 3. Criteria 3 and 4: wake task from S3 sleep and from hibernate; Chrome launch and `onStartup`

For these two runs Chrome must be started BY THE TASK. So:
- `chrome://settings/system`: turn **Continue running background apps...** OFF, and on the probe page click nothing else. (Revoke the permission if you want a clean run: `chrome://extensions`, probe, Details, Permissions.)
- Close ALL Chrome windows and confirm in Task Manager that no `chrome.exe` is left.
- Keep the charger plugged in.

3.1. **Run A, S3 sleep.** In a normal PowerShell:
```powershell
powershell -ExecutionPolicy Bypass -File "$R\companion\windows\probe\wake-probe.ps1" -DelayMinutes 5 -Label S3 -LaunchChrome -ChromeUserDataDir $UD -ChromeProfile $PR
```
It prints the fire time and the log path. Optional: in an elevated PowerShell run `powercfg /waketimers` and keep the output (must list the task `ShopBadwillWakeProbe-...`).
3.2. Within 1 minute of that output: Start, Power, **Sleep** (this is S3 on your machine; `powercfg /a` showed Standby S3 is the only sleep state). Do not touch the machine. Do not close the lid unless that is what you do at night; if you want to test the lid, say so in your reply.
3.3. Wait up to 10 minutes. Expected: the laptop wakes itself ~5 minutes after you ran the script, the screen may stay off, and Chrome opens. If it did NOT wake by itself after 10 minutes, press a key and note "did not wake by itself". Either way the log tells us.
3.4. Wait 2 minutes, open the probe page, **Export JSON** as `runA-export.json`. Then close all Chrome windows.
3.5. **Run B, hibernate.** Same as 3.1 but:
```powershell
powershell -ExecutionPolicy Bypass -File "$R\companion\windows\probe\wake-probe.ps1" -DelayMinutes 6 -Label hibernate -LaunchChrome -ChromeUserDataDir $UD -ChromeProfile $PR
```
Then hibernate within 1 minute: in PowerShell run `shutdown /h` (or Start, Power, Hibernate if shown). Wait up to 12 minutes. Expected: the laptop powers on by itself at ~6 minutes. If you have to press the power button, note it. Export JSON as `runB-export.json`.
3.6. **Optional Run C, "Important wake timers only":**
```powershell
powercfg /setacvalueindex SCHEME_CURRENT SUB_SLEEP RTCWAKE 2
powercfg /setactive SCHEME_CURRENT
```
Repeat Run A with `-Label S3-important-only`. RESTORE afterwards (important):
```powershell
powercfg /setacvalueindex SCHEME_CURRENT SUB_SLEEP RTCWAKE 1
powercfg /setactive SCHEME_CURRENT
powercfg /q SCHEME_CURRENT SUB_SLEEP RTCWAKE
```
(AC index must read `0x00000001` again.)
3.7. **Optional Run D, on battery:** unplug, repeat Run A with `-Label S3-battery`. Replug afterwards. Expected: does not wake (DC wake timers are Disabled in your plan). Tells us whether the unplugged case matters.
3.8. Cleanup check (should say no leftover tasks):
```powershell
powershell -ExecutionPolicy Bypass -File "$R\companion\windows\probe\wake-probe.ps1" -Mode Cleanup
```

## If something goes wrong

- Task left behind: run step 3.8.
- Power plan not restored: run the restore commands in 2.5 / 3.6.
- Script blocked by policy: the commands above already use `-ExecutionPolicy Bypass`.
- Laptop did not wake: that is a valid result; paste the log (it still records `SCHEDULED`; the task has `StartWhenAvailable`, so it will run when you wake the machine and the log shows the wake source).
