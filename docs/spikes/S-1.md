## Method

- Every request went through `scripts/capture-fixtures.ts`:
  - headless Playwright Chromium with the browser's own UA (`HeadlessChrome/153`, no spoofing);
  - no cookies (`credentials: 'omit'`, cookie jar cleared before each render) and no `Authorization`;
  - a deny-by-default URL guard: no `/categories/listing`, no `/shopgoodwill/*`, no `/checkout/`, no sign-in pages, no write or session endpoints.
- Page renders blocked images, fonts, media and every third-party host (ads, analytics, reCAPTCHA). Each render therefore cost SGW only its own app files and the XHR the app makes.
- buyerapi reads came from a minimal MV3 extension page with `host_permissions` for buyerapi. That is the same origin class as the shipped background.
- **15 of 25 requests**, the closest two **121.0 s** apart (end to start). No 403, 429, 5xx or challenge. No login, no write.
- The three renders also made 37 first-party app-file requests and 12 buyerapi XHRs of their own, listed per render in `request-log.json` `pageInitiated`.
- `scripts/sanitize-fixtures.ts` then built `test/fixtures/sgw/{json,html}/`, `manifest.json` (provenance) and `request-log.json`. The build fails if any original title, seller name, item id, image URL, JWT or secret header survives.

## Verdicts

### 1. `serverTime` format ⚠: naive Pacific wall time with milliseconds

| Sample | `serverTime` | HTTP `Date` | serverTime + 7 h |
|---|---|---|---|
| #5 (page XHR) | `2026-10-07T20:09:15.967` | 03:09:16 GMT | 03:09:15.967Z |
| #11 | `2026-10-07T20:21:29.213` | 03:21:29 GMT | 03:21:29.213Z |
| #12 | `2026-10-08T00:07:55.423` | 07:07:55 GMT | 07:07:55.423Z |

- `serverTime` has no offset. It is Pacific wall time (PDT, UTC−7, on these dates) and agrees with the `Date` header to the second.
- It always carried 3 fractional digits. Other naive fields vary:
  - `endTime` is usually whole seconds (`…T20:39:00`); 3 of 160 search rows had a fraction;
  - bid times trim trailing zeros (`…T18:40:11.35`).
- Parse every one with `America/Los_Angeles` (`SGW_TIME.naiveIso`), as PLAN already assumes.
- `Dashboard/GetCurrentTime` (the site POSTs a null body) returns the envelope with `data: "10/07/2026 20:09:15"`: `MM/dd/yyyy HH:mm:ss` Pacific, 1 s resolution.
- **Implication:** `ItemDetail.serverTime` is the better clock sample (ms). The contract (`ItemDetail.serverTime` / `serverTimeRaw`, `ClockSample.source`) needs no change.

### 2. Item-page DOM ⚠: settled for the logged-out page (#5)

- The page hydrates client-side (SSR skeleton first) under `app-detail`. Selectors are in `SGW_SELECTORS.item`; each one was checked to match exactly one element in `html/item-page-logged-out.html`.
  - **Title:** `h1[id]`, whose `id` is the item id (desktop only; the mobile title is elsewhere). The item id comes from the URL first.
  - **`app-bidding-control`:**
    - time left: `strong + span.text-danger`, "29m 43s";
    - bid count: `a[aria-label$="See all bids"]`;
    - Current Price and Minimum Bid: label/value rows (`.col-8` label, `.col-4` value);
    - max-bid box: `input#currentBid`;
    - "Place My Bid": `button.btn-purple`, which opens `p-dialog#placeMyBid`.
  - **Favourite heart:** `app-image-gallery a.btn-heart`, whose `aria-describedby` is the item id. A bare `app-detail a.btn-heart` also matches the 5 seller cards further down.
  - **Tabs** (`#tabs-detail`): Item Info, Shipping (`app-shipping-tab`, with `select#country`, the ZIP input and "Get Estimate"), Seller Info (`app-seller-info-tab`, "Location: City, ST") and Bid History. `#item-description` is rendered twice.
- The 5 "more from this location" cards are the same `app-home-product-items` component that search uses:
  - `div.item-col > app-home-product-items > div.feat-item`;
  - `a.feat-item_name[id={itemId}][href="/item/{id}"]`, `p.feat-item_price`, `a.btn-heart[aria-label="Add to your Favorites list"][aria-describedby={itemId}]`;

  - This matches the brief's grid-card DOM exactly. Each card has **two** `a[href^="/item/"]`, so dedupe by id. The page's skip link is also `/item/{id}#maincontent`, so card selectors are card-relative.

### 4. Search URL ↔ ItemListing body mapping ⚠: settled from the bundle

- The site's own `buildSearchQueryString` (main bundle) maps 31 URL params 1:1 onto body fields. This is now `SGW_SEARCH_URL_PARAMS`:

- `T-50`'s list (`st, c, s, lp, hp, spo, snpo, socs, sd, sca, col, p, ps, desc, layout`) is a subset; keep the rest in `extra`.

### 5. Which flows reCAPTCHA gates ⚠ (observation only)

The item and help DOMs have no reCAPTCHA script, iframe or `.grecaptcha-badge`. The home DOM was never checked (#2's in-page script failed), so for home the evidence is network-only.

- **Not in the item-page chunks.** The chunks holding the bid modal and PlaceBid (540) and CalculateShipping (813) have no captcha reference.
- **Not observed:** the sign-in page (the guard never loads it) and the logged-in bid modal. USER STEP S-1 asks the user to note whether either shows a challenge.
- **Implication:** no evidence that bidding, favourites or search are reCAPTCHA-gated. The extension still stops and notifies on any challenge (§7, "No evasion").

### 6. Goodwill Canada "last-second bids" warning ⚠: **present in SGW's own help center**

- Help Center → Auctions → "Why was my bid in the last seconds of an auction not accepted?" (#9 list, #13 answer, last updated 2024-04-04):

  > "To view an auction in real time you must continuously refresh the auction page in order to keep up with the auction clock. When bidding in the last seconds of an auction the clock is running as you refresh the page and type your bids, therefore your bid may not be accepted and processed before the auction closes."

- **Implication:** SGW itself warns that last-second bids may not be processed. That supports the default lead (8000 ms) and the dry-run gate. It is not a reason to fire earlier than the user chose.

### 7. Other ⚠ items settled by anonymous reads

- **New-account cap: confirmed** (#14, updated 2026-01-29):
  - accounts under 30 days may be high bidder on at most **15 active auctions** at a time;
  - any account with **15 or more open unpaid items** has bidding suspended until it drops below 15.
  - Add to the risk register / snipe pre-checks (a rejected bid may mean this cap).
- **Early end: confirmed** (#15, updated 2024-04-23): an auction ended early has its bids **retracted** and the bidder is emailed. This is the `ended-early` outcome.
- **Soft close: one data point, no extension** (#5 vs #12; S-3 owns the verdict):
  - the closed auction's last bid was at `20:38:54.16`, **5.84 s** before `endTime` `20:39:00`;
  - `endTime` was unchanged after close.
- **Closed markers** (#12 vs #5): `bidHistory.auctionClosed` and `isItemEndTimeExpire` turn `true`, and `remainingTime` becomes `"Auction Ended"`. `minimumBid` keeps advancing (82 after a final 81). `SGW_FIELDS.detail.closed` lists them.
- **Search-row `minimumBid` is the starting price:** it equalled `startingPrice` on all 160 rows of #3, #4, #8 and #10, including 72 rows with bids. ItemDetail `minimumBid` is the next acceptable bid (#5: `currentPrice` 67.01 + `bidIncrement` 1.00 = `minimumBid` 68.01). Use the ItemDetail value for caps and snipes.
- **Seller state source (CONTRACT-DECISIONS #11): found, so keep `Listing.sellerState` and the `location` condition.**
  - Search rows carry only `sellerId` (no name, state or pickup flag).
  - ItemDetail has `pickupState` on every sampled item (2 items from 2 sellers, one pickup-only), plus `sellerCompanyName`.
  - `Seller/GetSellerInfo/{sellerId}` (anonymous; the item page calls it itself) returns `state`, which a per-seller cache can apply to search rows.
- **Shipping:**
  - ItemDetail `shippingPrice: 0` with `allowShippingCalculation: true` means "calculated", not free (the page shows "Estimate Shipping"). `handlingPrice` is separate (5.00 on #5).
  - **`CalculateShipping` request shape: settled from the bundle** (chunk 813, `getShippingRate`): `POST ItemDetail/CalculateShipping {itemId, country, province, zipCode, quantity, clientIP}`. The **response shape is still open** (USER STEP S-1, step 8).

## Reproduce

1. Put step files in `test/fixtures/sgw/raw/queue/` (shape: `CaptureStep` in `scripts/capture-fixtures.ts`).
2. Run in the foreground: `pnpm exec tsx scripts/capture-fixtures.ts once`. It enforces the cap and spacing from the persisted `raw/request-log.jsonl`, and refuses robots-disallowed URLs.
3. Rebuild the fixtures: `pnpm exec tsx scripts/sanitize-fixtures.ts`. The salt in `raw/.salt` keeps the remapped ids stable.
