# S-8 · Wake-from-sleep feasibility on Windows

Card T-14. Status: **stage 1 done (read-only diagnostics + tooling); stage 2 awaiting USER STEP S-8** (`docs/USER-STEPS/S-8.md`).

## Why

Snipes end while the user is asleep. Per architecture §1.4, T1 (extension + keep-alive) needs the PC awake and the browser running at fire time. T2 (wake-and-launch via Task Scheduler) needs a wake timer that actually works on this hardware and a browser start that runs the extension's `onStartup` reconcile quickly. Nothing below was changed on the machine; all values are read-only snapshots.

## Stage 1: read-only diagnostics (2026-10-07, Windows 11 Pro 10.0.26200, Lenovo 83F5 "LEGION", user `insan`)

### `powercfg /a`

```
The following sleep states are available on this system:
    Standby (S3)
    Hibernate

The following sleep states are not available on this system:
    Standby (S1)   The system firmware does not support this standby state.
    Standby (S2)   The system firmware does not support this standby state.
    Standby (S0 Low Power Idle)   The system firmware does not support this standby state.
    Hybrid Sleep   The hypervisor does not support this standby state.
    Fast Startup   This action is disabled in the current system policy.
```

Reading: **no Modern Standby (S0ix).** Sleep is classic S3, and the OS can also hibernate (S4). Classic S3/S4 honour RTC wake timers when the firmware supports them (firmware support is what the user test measures). Because there is no Modern Standby, there is no "network connected standby" and no restriction of wake timers to the Modern Standby maintenance windows. Hybrid sleep is unavailable only because a hypervisor (WSL / Hyper-V) is present. Fast Startup is off, so "shutdown" is a real cold boot.

### Active plan and `powercfg /q SCHEME_CURRENT SUB_SLEEP`

Active scheme: `381b4222-f694-41f0-9685-ff5bb260df2e (Balanced)`.

| Setting (alias) | AC | DC (battery) |
|---|---|---|
| Sleep after (STANDBYIDLE) | `0x0` = **never** | `0x0` = **never** |
| Hibernate after (HIBERNATEIDLE) | `0x2a30` = 10800 s = 3 h | `0x2a30` = 3 h |
| Allow hybrid sleep (HYBRIDSLEEP) | 0 (Off) | 0 (Off) |
| **Allow wake timers (RTCWAKE)** | **`1` = Enable** | **`0` = Disable** |

`RTCWAKE` possible values: `0` Disable, `1` Enable, `2` Important Wake Timers Only.

Reading:
- On AC, wake timers are already enabled; the user says the laptop is plugged in when auctions end, so the DC "Disable" does not matter, **unless the charger is unplugged or the laptop is on battery** (then a wake task will not wake it).
- Sleep-after is "never" on both AC and DC. The machine will not idle-sleep on its own with the current plan; the risk to sniping is a manual/lid sleep, a Windows Update restart, or Lenovo Vantage/OEM policy. (For criterion 2 the user must temporarily set a short sleep timeout, otherwise there is nothing for keep-awake to prevent. Documented in the USER STEP.)
- The option "Important Wake Timers Only" exists on this machine (value 2); criterion 3 includes an optional run with it.
- Only the Balanced scheme was inspected; other schemes were not enumerated.

### Chrome "Continue running background apps when Google Chrome is closed"

- Policy: neither `HKLM\SOFTWARE\Policies\Google\Chrome` nor `HKCU\SOFTWARE\Policies\Google\Chrome` exists, so **no enterprise policy (`BackgroundModeEnabled`) governs it.** The setting is the per-user default (ON by default on Windows; stored as `background_mode.enabled` in Chrome's `Local State`).
- Per-user setting: **not readable on this machine.** Chrome 148.0.7778.96 is installed per-user (`%LOCALAPPDATA%\Google\Chrome\Application\chrome.exe`) but `%LOCALAPPDATA%\Google\Chrome\User Data` is **empty** (no `Local State`, no profile). So Chrome has not been run with the default user-data directory on this Windows account, or the user's profile lives elsewhere (custom `--user-data-dir`, or a different Windows account). **Open question for the user (step 0 of the USER STEP): which user-data dir/profile do they actually use** (`chrome://version` → "Profile Path"). The probe script takes `-ChromeUserDataDir` and `-ChromeProfile` for this.
- Autostart: HKCU Run key currently has no `GoogleChromeAutoLaunch_*` entry (consistent with Chrome never having been run here with the background permission/setting).

### Pre-registered interpretation (to avoid bending results afterwards)

- T2 viable iff: wake task fires from the sleep state(s) the user actually uses on AC, wake→`onStartup` is comfortably below the arming margin (the snipe wake alarm is at T−5 min; T2 should wake at T−10 min or earlier), and Chrome (not just any window) starts with the profile and runs `onStartup`.
- T1 viable iff: criterion 1 shows Chrome stays alive with all windows closed (or the user keeps a window open), and criterion 2 shows keep-awake holds the machine awake while idle with the plan's sleep timer. Firefox has neither, so on Firefox T1 means "PC awake and Firefox open".
